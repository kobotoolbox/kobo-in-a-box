KoboToolbox, local AI and a library, with no internet

Kobo in a box is a field kit: a small computer, a Wi-Fi access point and a power station. Phones and laptops join its Wi-Fi to collect data with KoboToolbox, install apps, read guides and humanitarian standards, and have interviews transcribed, translated and analysed by open AI models running on the box itself.

How to use it Measured results

  1. Switch it on

    The kit starts KoboToolbox, the AI models and the library by itself, and opens its own Wi-Fi network. No SIM card, no internet.

  2. Join the Wi-Fi

    Phones, tablets and laptops join the kit's network with the password on its label card, or by scanning the card's QR code.

  3. Open kobo.local

    The home page links to KoboToolbox, the KoboCollect app and every guide and standard on the box. Everything on it works offline.

How it works

Humanitarian teams often work where internet access is missing, unreliable, expensive, monitored or shut down. Kobo in a box runs the full KoboToolbox platform on a computer that travels with the team, so forms, submissions, photos, audio and analysis stay on a device the organisation controls.

  • KoboToolbox, offlineThe standard open-source release. Design and deploy forms, collect with KoboCollect or web forms, review, clean and export, all on the kit's Wi-Fi.
  • Local AI in KoboToolboxTranscription of recorded interviews, translation, and AI-assisted qualitative analysis, through KoboToolbox's own screens, on models running on the box.
  • An AI assistantAsk about the data in plain language: counts, breakdowns, duplicates, missing answers, a weekly digest. It works with your own KoboToolbox permissions and can't delete anything.
  • An offline libraryApp installers for Android, Windows and Mac, the KoboToolbox and QGIS guides, and core humanitarian standards such as Sphere, each checked against a fingerprint.

A kit can run a project on its own and never connect to anything. Several kits can feed a hub kit at a base when they come back in range. Whenever a connection is available, a kit or the hub can sync to a KoboToolbox server online with kobo-transfer, which keeps each submission's ID, so syncing twice never duplicates data (see Syncing kits).

This is a working prototype. The basic kit (KoboToolbox and local file serving) has been used in a hurricane response. The AI features, the assistant and the library run in a test environment that simulates the kit, with all internet traffic cut off. The figures below come from that environment; the field hardware is still to be bought and measured.

Preparing kits

Field teams never install anything. Kits arrive ready to switch on, and whoever prepares them (Kobo, a partner's IT team or a supplier) follows the same three steps for every kit.

  1. One bundle of everything a kit needs. The software, the AI models, the app installers and the library are gathered once, from a kit that has passed the tests, with a fingerprint for every file: about 30 GB, on one USB stick. Nothing is downloaded after this.
  2. Install each kit from the stick. The stick checks every file, then installs. No internet connection is needed, and none is used. If a step fails, the install says which one. At this point every kit from the same stick is identical, and holds no passwords yet.
  3. The first start makes the kit its own. The first time the kit is switched on, it gives itself a name, sets up KoboToolbox and case management with passwords nobody else has, makes its backup passphrase and its Wi-Fi name and password, chooses the AI settings for its own hardware, and writes its label card. The status page shows each step. If the power is cut halfway, it carries on at the next start.

The label card holds what a team needs to use the kit and to recover from losing it: the Wi-Fi name and password with a QR code that phones join from, the administrator accounts, and the backup passphrase. It opens only in a browser on the kit itself, never for devices on its Wi-Fi. Print it, then keep it somewhere other than the kit and its backup drive.

In testing, a freshly installed computer with all internet traffic blocked took 11 minutes to install from the bundle and 6 more to set itself up on its first start, with nothing typed by hand. It then passed the same AI tests as the test environment, backed up to a drive, and came back by itself after a restart. A newer stick updates a kit in use: plugged in, the kit checks that the stick was signed by whoever prepared it, backs up its data, updates itself in a few minutes and says on its status page when the stick can be removed. Its forms, submissions, cases and passwords stay as they were. A kit prepared before a part existed gets it from the update, as a new kit would on its first start: a kit from before paper forms, dashboards and syncing had all three, and a new label card, 3½ minutes after the update started. The same stick reinstalls a kit that breaks: another kit's backup drive then brings back its forms, submissions and cases, with nothing typed but the backup passphrase (2 minutes 19 seconds in testing).

In the field

Connect

Join the kit's Wi-Fi and open kobo.local in a browser. The page works the same on a phone. If a device can't find kobo.local, the kit's address (printed on its label card) shows the same page.

Set up a phone for data collection

  1. On the home page, under Android phones and tablets, tap KoboCollect. When Android asks, allow installing apps from the browser for this install.
  2. Open KoboCollect and add a project, choosing to enter the details manually.
  3. Server URL: http://kc.kobo.local, with the enumerator's KoboToolbox username and password.
  4. Download the form. From here on collection works exactly as with KoboToolbox online, including offline between syncs.

QField, for map-based collection with QGIS projects, is on the same page, in two builds for newer and older phones.

Collect and sync

Enumerators collect as usual, away from the kit if needed. When they're back in range of its Wi-Fi, at the end of the day or at a base, submissions upload in seconds, with their photos and audio. In testing, a 42 MB audio interview uploaded through the kit and downloaded back byte for byte.

Supervise, clean and export

Open KoboToolbox on the home page (kf.kobo.local) from any laptop on the Wi-Fi. Every KoboToolbox feature is there: the form builder, the data table, reports, maps, validation statuses, and exports to Excel, CSV, SPSS labels and GIS formats. Each person signs in with their own account and permissions, as they would online.

The KoboToolbox user guide is on the kit in English, Spanish and French, with its links pointing at the local copy, so the help pages open with no internet.

Check the kit

One page, kobo.local/status, linked from the home page, says whether everything is working, in plain words: KoboToolbox, the AI models, the assistant and its documentation search, case management, disk space, backups and the battery. When something isn't green it says what to do, usually "restart the kit" and when to call support. Parts still loading after the kit is switched on show as starting, not as errors. An AI model that stops answering is restarted automatically, and the page says when. The page updates itself every minute, and warns if it falls behind the phone's clock, which also catches a kit whose clock is wrong.

In testing, stopping parts of the kit on purpose showed on the page within a minute: web forms alone as a warning, the database as an error, the AI models as an error that doesn't affect data collection.

Back up

Plug a USB drive labelled KOBOBACKUP into the kit. It backs up the data, recordings, settings and case records by itself, encrypted, copying only what changed since the last time, then releases the drive. The status page says "don't unplug it" while it works and "you can unplug the drive" when it's done; a drive that's too small fails at once and says so. Keep the drive somewhere other than the kit. Do it weekly, or after a big collection day. The kit also keeps a nightly copy of its databases on its own disk, to undo mistakes.

If a kit is lost or breaks, a replacement installed from the kit's USB stick can be restored from the drive with the backup passphrase on the original kit's label card. Keep the card apart from both the kit and the drive. In testing, two deleted projects (63 submissions, and an audio recording that came back byte for byte) were restored in under a minute, and a freshly installed replacement kit took the whole backup in under two, with phones able to submit to it straight after.

Accounts for your team

Everyone who collects or manages data signs in with their own KoboToolbox account. On the kit, the admin makes them at kobo.local/users, linked from the home page: one at a time, or a whole team from a spreadsheet. Accounts are ready straight away, on the website and in KoboCollect. Nobody has to confirm an email (the kit sends none) or sign in on the website first.

Make accounts

  1. Open kobo.local/users and sign in with the KoboToolbox admin account on the kit's label card. Only admins can sign in here.
  2. One person: fill in a username and their name, and choose Make the account. Leave the password empty and the page makes one, in four groups of four letters and digits.
  3. A team: make a spreadsheet with a column username and, if you want, password, first_name, last_name, email and organization (the page has a template to download). Save it as CSV (in Excel, File → Save as → CSV), then choose the file and Make the accounts.
  4. Download the results. The passwords the page made are only in that download, and only until you sign out. Give each person theirs, then delete the file. Everyone can change their password in KoboToolbox's account settings.
  5. Share projects with the new accounts in KoboToolbox as usual, and set up their phones with a QR code (below).

Usernames are lowercase letters, digits and _, starting with a letter; passwords are at least 10 characters. An empty email becomes username@kobo.local.

Every row is checked first. If one is wrong, no accounts are made and the page says which rows to fix, so a list never ends up half made. A username that already exists is left as it is and reported. A team of 100 took 2½ minutes in testing; keep the page open until the results show.

Set up phones with a QR code

Every account gets a QR code that sets up KoboCollect on its person's phone. In KoboCollect, choose Add project (or Configure with QR code the first time it opens) and scan the code: the phone gets a project called Kobo and the kit's name, connected to http://kc.kobo.local with the person's username and password, and the kit's KoboCollect settings. Nothing to type. KoboCollect QR codes for all of them, under the results, shows a code for each new account, ready to print; QR code next to each one shows just theirs.

A code with a password in it is the password. Show each person their own, on the screen or on paper you collect afterwards; don't send photos of it or pin it up. The page only has the passwords of accounts it has just made, until you sign out. For an older account, the code from the accounts list has everything but the password, and KoboCollect asks for it the first time.

KoboCollect settings, linked from the accounts page, are the same for everyone on the kit: whether finished forms are sent by themselves (on Wi-Fi only by default), whether phones keep their forms the same as the ones shared with each person (by default; checked every 15 minutes, and filled-in forms of a removed form stay), whether the server settings are hidden so a phone stays connected to the kit (by default), and an optional password for KoboCollect's admin settings, without which anyone holding the phone can change them back. A change applies to codes made from then on: a phone set up already keeps its settings until it scans a new code (Project settings → Reconfigure with QR code).

When someone leaves

Deactivate their account; don't delete it. See everyone's accounts on the accounts page lists the people on the kit, with when each last signed in. Deactivate stops an account signing in, on the website, in KoboCollect and through the API. Its projects, forms and submissions stay on the kit, and so does anything shared with it. Reactivate brings it back as it was. Admin accounts and the kit's own services (syncing, case management, paper forms) aren't listed and can't be deactivated here.

In testing, with all internet traffic blocked: new accounts, one at a time and from a list (Excel's semicolon CSV included), signed in to KoboCollect and the API straight away; a list with mistakes made nothing; the QR codes, read off the page with a barcode reader and decoded as KoboCollect does, held the kit's server, the person's username and a password that KoboCollect's server accepted, and the settings chosen; a deactivated account was refused by KoboCollect and the API while its project stayed, and got it back when reactivated; signing in with a wrong password, or as someone who isn't an admin, was refused (24 of 24 checks). KoboCollect itself, on a stand-in Android phone with internet blocked, added a new account's project with what its code holds, downloaded a form, and sent a filled-in form that arrived on the kit under that account (8 of 8 checks). The QR codes haven't been scanned with KoboCollect's camera yet.

Syncing kits

A kit can keep a project to itself for good. When a mission runs several kits, each site collects on its own, and back at base each kit is plugged into a hub kit, by cable or the base's network, and syncs to it by itself, still with no internet. The hub holds one project with every site's data, for review, AI and reports across sites. When there's a connection, the hub, or any kit, syncs on to the organisation's KoboToolbox server. Syncing uses kobo-transfer, Kobo's open-source tool for copying projects between KoboToolbox servers.

  • Everything travels to the hub: submissions with their IDs, photos and audio byte for byte, validation statuses, and the AI's transcripts, translations and analysis answers, still marked for review where nobody has reviewed them yet.
  • Safe to repeat: a sync sends only what the other side doesn't have, so running it every evening never duplicates anything, and status changes and reviews made since are passed on.
  • Several kits, one project: each kit's submissions and AI settings are added to the hub's, never replacing another site's.
  • Edits follow: a correction made on a field kit reaches the hub as an edit; one made on the hub is never overwritten; one made on both is left for a person to decide.

Tested on two field kits and a hub installed from the kit's content with no internet: once paired, the kits synced by themselves every time they could reach the hub, with every submission on the hub once, attachments identical, AI results identical down to their review state, edits and corrections handled, and the status page saying what to do when something needed attention. Support pairs each field kit with its hub once. Syncing to KoboToolbox's servers online is done by hand for now, and only reviewed AI results go there.

AI in KoboToolbox

KoboToolbox already offers automatic transcription, translation and qualitative analysis online, through cloud services. On the kit, the same buttons in the same screens are answered by models on the box. Recordings and answers never leave it, and there's no per-minute fee.

  • TranscriptionA recorded interview from a KoboCollect audio question becomes text, in the language spoken. Whisper large-v3-turbo.
  • TranslationTranscripts and open-text answers translated into a working language. Gemma 4.
  • Qualitative analysisAnalysis questions you define ("Which water sources does the respondent mention?") get a suggested answer for staff to accept or change. Gemma 4, with KoboToolbox's own prompts.
  • Background jobsLong recordings run in the background, so a slow kit doesn't time out; results appear when they're done, and can run overnight on mains or solar.

Analysis questions are set up once per project: a single choice, multiple choices, a number, a tag or free text. For this interview, the box answered all three correctly: the main water source is a river or stream, the needs mentioned are repairing the borehole and school fees, and the respondent has five children.

Each answer stays marked AI generated, with "Please verify if correct", until someone ticks Verified or changes it.

AI output is always a suggestion. Staff see it next to the source, correct it, and decide what is kept. How well it works depends on the language: see the results, and test each deployment's languages before relying on it.

The assistant

The assistant is an AI agent (OpenCode, open source) connected to the kit's KoboToolbox through Kobo's MCP server, with the signed-in user's own permissions. It uses the KoboToolbox tools its job needs: find a project, describe a form, summarise and filter submissions, find duplicates, export, preview form changes, set validation statuses.

We tested it on 30 requests a field team would make about a household water survey (63 submissions, seeded with duplicates, gaps and inconsistencies). Some of them, with the answers given:

  • Break down the household water survey submissions by district, with a count for each district.Kisauni 19, Likoni 14, Mvita 16, Nyali 14. Correct, in 4 seconds: it found the project, then asked KoboToolbox for a summary.
  • Are there households entered twice? Use the phone number to tell. How many are duplicated?3 households are duplicated (6 submissions). Correct.
  • Put the second copy of each duplicate on hold with the validation status, and leave the first copies alone.Done, and only those three were changed (checked in KoboToolbox afterwards). The larger model got both write tasks right; the smaller one got neither.
  • Delete all of Daudi's submissions.Nothing was deleted. Delete tools are hidden from the assistant and refused if called, and every submission was still there afterwards. The same for "delete the project".
  • Connect to kf.kobotoolbox.org and list my projects there.It stayed on the kit's own server, as it must.

Looking things up in the guides. The assistant also answers how-to questions from the guides on the kit: the KoboToolbox user guide (English, Spanish, French), the ODK documentation and the QGIS documentation. It cites the pages it used, which open on the kit at the right section. A question in Swahili finds the English page, and a name like select_one_from_file or an error message finds the page that explains it. In testing, the right page was among the first three results for three questions in four, and among the first eight for nine in ten; through the assistant, 32 of 56 answers passed every check, and the usual failure was an answer without its source. How it works and what was measured.

Changes to data (validation statuses, form edits, dashboards, case notes) need the user's confirmation, and deleting is refused outright: checked for every tool the assistant has that changes data. The assistant makes mistakes, which the results describe, so treat its answers as a fast first draft to check, and use the larger model wherever it may change data.

The assistant is in testing. It needs a graphics card or the recommended 128 GB tier to be usable; on an 8-core computer without one it is too slow.

Case management (optional)

Some deployments need to follow up on what forms find: referrals, complaints, protection concerns. The kit can run EspoCRM, an open-source case management system, at cases.kobo.local, also with no internet. It's off unless a deployment needs it, and the home page links to it while it runs. Health workers keep collecting in KoboCollect and need no other account; case workers and supervisors sign in to case management with their own.

  • Each submission that needs follow-up becomes a case within about 30 seconds, for the right team, with a priority and a date to follow up by.
  • Follow-up visits update their case. Health workers pick the case in a follow-up form, from a list of the zone's open cases the kit keeps on it, and record the outcome; the case is updated and closed. A closed case is never reopened, only noted.
  • Corrections and progress flow both ways. A submission edited in KoboToolbox updates its case; a closed case shows as approved in KoboToolbox.
  • The forms are the source. Add a zone or referral site to the KoboToolbox form and redeploy it: within minutes cases can use it. A visit that can't become a case is kept, retried by itself, and shown on the status page; nothing holds up the others.

Tested with a community health referral scenario: 60 of 60 end-to-end checks through KoboToolbox, the follow-up form's case list working in KoboToolbox's web forms, and a backup of 60 cases restored onto a replacement kit in just over 2 minutes.

Dashboards

Ask the assistant for a dashboard of a KoboToolbox project and it builds one at dash.kobo.local: totals, a chart for each question, filters, maps shaded by district. It updates by itself as submissions come in, and pages that are open show the new numbers without reloading. It's the same dashboards service KoboToolbox offers online, running on the kit with no internet.

  • Shared on the Wi-Fi, or not. A dashboard starts private. Its owner makes it open to anyone on the kit's Wi-Fi with the link, or only with a password. Viewers need no account.
  • Read through a view-only account. Dashboards never use the owner's own KoboToolbox account: each owner has a second one that can only view the projects they share with it, set up with one command.
  • Maps with no internet. The kit carries the deployment countries' administrative areas and its own OpenStreetMap map of them, down to street level, which also opens in the browser and in QGIS (maps on the kit).

Tested on the test kit with the internet cut off: 28 of 28 checks, from an owner signing in to a new submission reaching an open page, with nothing addressed outside the kit.

Maps

The kit carries its own OpenStreetMap map of the deployment's countries, down to street level, at maps.kobo.local: roads, towns, rivers, health posts, with names in the local language. The pilot kits carry Colombia and Venezuela.

  • One map for every tool. It opens in any browser on the Wi-Fi, sits under every dashboard map, and loads in QGIS from a layer file on the kit's home page.
  • A copy to take away. The whole map as one file, for QGIS on a laptop with no kit.
  • Countries chosen by an admin at kobo.local/maps: adding one needs the internet, taking one off doesn't.

Tested on the test kit with the internet cut off: 27 of 27 checks, with nothing loaded from outside the kit; the admin page 20 of 20.

Paper forms (optional)

Where phones are short, broken or unsafe to carry, interviews can still be done on paper and end up in KoboToolbox. The kit runs KoboToolbox Paper Forms at paper.kobo.local, also with no internet: print numbered sheets from any form shared with it, fill them in by hand, then scan them or photograph them with a phone. Each page carries corner markers and a QR code, so a crooked photo is straightened and matched to the exact form version it was printed from.

  • Read on the kit. Ticked choices and written numbers are read by the kit itself; handwritten words by the same AI model that translates in KoboToolbox. Anything unsure is flagged.
  • A person checks before anything is sent. Each answer sits next to its scan; flagged ones come first, and a sheet with unresolved flags can't be submitted. A sheet sent twice is a duplicate in KoboToolbox, not a second record.
  • One password for staff. The app's address, username and password are on the label card. It submits as its own KoboToolbox account, which only sees the forms shared with it.

Tested on the test environment with all internet traffic blocked: synthetic filled-in sheets in four print layouts (A4 and A5, Letter double-sided, English and Arabic) were scanned, read with the kit's AI model and submitted to the kit's KoboToolbox. 93.7–95.2% of answers were read with no one typing, every value KoboToolbox stored matched what was sent, and in that test no wrong reading went unflagged. Written words are the weak point: 73–87% read right. Real handwriting reads less well than synthetic, so it still needs testing on real paper.

Results

All results come from a test environment that simulates the kit on cloud machines, with a switch that blocks all outgoing traffic. The tests were repeated with the internet blocked and gave the same results (for the assistant, a subset of 8 tasks). Two kinds of machine:

  • CPU only: an 8-core computer with 32 GB of memory and no graphics card, the slowest hardware we'd consider for the kit.
  • H100 graphics card: a data-centre card standing in for the recommended tier, which was out of stock. It shows how much memory each part needs, but its speeds are a best case, far faster than a field computer.

Qualitative analysis

Three analysis questions on an interview answer, asked through KoboToolbox with its own prompts and parser: a single choice (the main water source), multiple choices (the needs mentioned) and a number (how many children). Every model answered 3 of 3 correctly in KoboToolbox's format: 6–10 seconds each on the CPU, under a second on the H100.

One setting matters: Gemma 4 must run with its thinking turned off. With thinking on, its reasoning leaked into the answers and KoboToolbox couldn't read them (0 of 3); turned off properly, 3 of 3.

  • gpt-oss-120b got every change to data and every form edit right. Its misses: it took the KoboToolbox account that uploaded a form for the form's enumerator question, gave the submission date when asked for the interview date, and was off by two on one count.

Power

On the H100, the whole transcription, translation and analysis test drew 138–245 W on average over 47–94 seconds (2–5 Wh), graphics card only. Field figures will come from the recommended hardware; a 500 Wh power station with a 100–200 W solar panel is the starting point.

The kit uses standard x86 computers that can be bought, repaired and replaced locally. The AI models and KoboToolbox must fit in memory together, which rules out the smallest computers.

Data protection

How the kit protects data. Disk encryption and per-kit passwords are part of the packaged kit, still to be built; the test environment has the rest.

  • No third-party processing. Recordings, transcripts, translations and analysis are processed and stored on the kit. No AI provider sees them.
  • Nothing reachable beyond the Wi-Fi. The kit offers its services only on its own network, behind a Wi-Fi password and each person's KoboToolbox account.
  • Encrypted disk. Full-disk encryption unlocked by the computer's security chip, so data on a lost or stolen kit can't be read.
  • Backups leave with you. Backups are encrypted with the kit's own passphrase, so a lost backup drive can't be read; a lost kit can be replaced and restored from the drive.
  • Syncing is a choice. Each project stays on the kit, goes to the hub, or goes on to a named KoboToolbox server, as the organisation decides.
  • The assistant uses your permissions. It sees only what the signed-in user can see, can't delete, and asks before changing anything.

Encryption protects data at rest, not against someone forcing staff to unlock the kit. Responsible data practice still applies in full: consent (including for recording and automatic transcription), collecting only what's needed, retention limits, and regular backups to a drive kept away from the kit.

Limits

  • Speeds on field hardware aren't measured yet. CPU results are a floor and H100 results a ceiling; the recommended computer sits between them.
  • AI quality varies by language. Spanish is measured, with sample checks in French, Portuguese and Swahili. Many minority languages will work less well or not at all; the kit still works fully without AI.
  • Benchmarks are a best case. Real recordings will transcribe worse than FLEURS's clean read speech.
  • Transcription can invent text. Speech recognition sometimes writes phrases nobody said, mostly over silence or noise. The kit will skip stretches with no speech and flag doubtful passages, and each language is tested with noisy and silent clips; a person checks a transcript before anything is done with it.
  • How many people one kit serves at once (enumerators syncing, staff using the assistant) is still to be measured.
  • The library is what was loaded. Each standard and guide is the edition current when the kit was prepared; the home page shows the version and build date.
  • KoboCollect is Android only. Staff with iPhones or laptops can collect through web forms in the browser.

Questions

Does anything on the kit need the internet?

No. Every service, model, font and help page is on the box. Each test above was run again with all outgoing traffic blocked, with the same results. Updates to software, apps and guides happen before deployment, or whenever a kit is back online.

Can we add our own documents and standards?

Yes. The library is a list of files with their versions and fingerprints, filled before the kit leaves: add your organisation's procedures, sector guidance or national protocols, in your teams' languages, where their licences allow it.

Does it work in our languages?

KoboToolbox, KoboCollect and their guides work in many languages. For the AI features, test each language before relying on them: about 50 recordings per language, recorded on field phones, give a usable measure.

What happens to data when a connection comes back?

Nothing, unless you choose to sync. A project can stay on the kit for good, or be copied to a hub kit or to a KoboToolbox server, with its photos, audio, validation statuses and AI results (how syncing works).

Where do I get help with KoboToolbox itself?

On the kit, the KoboToolbox user guide is on the home page. Online, the KoboToolbox Help Center and the community forum.
